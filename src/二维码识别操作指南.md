# 二维码识别操作指南

> 若要完整启动“摄像头 → 二维码识别 → 7 寸屏显示”，优先看合并版：`src/二维码识别与屏幕显示操作指南.md`。本文只保留二维码识别节点的单独说明。

> 适用文件：`/userdata/dev_ws/src/dg_pkg/dg_pkg/qrcode_detector.py`  
> PC 路径：`<dev_ws>\src\dg_pkg\dg_pkg\qrcode_detector.py`  
> 当前节点名：`qrcode_detector`

## 1. 当前代码真实接口

当前二维码节点实际使用的是压缩图像话题 `/image`。

| 项目 | 当前真实值 |
|---|---|
| 启动命令 | `ros2 run dg_pkg qrcode_detector` |
| 订阅话题 | `/image` |
| 图像类型 | `sensor_msgs/msg/CompressedImage` |
| 发布信号话题 | `/sign_foxglove` |
| 发布原始数据话题 | `/qr_code/data` |
| 发布方向话题 | `/qr_code/direction` |
| 信号类型 | `std_msgs/msg/Int32` |
| 顺时针结果 | 二维码内容为 `1~9999` 的奇数，发布 `3` |
| 逆时针结果 | 二维码内容为 `1~9999` 的偶数，发布 `4` |
| 去抖参数 | `debounce_frames`，默认连续 5 帧一致才发布 |

注意：当前代码会发布 `/qr_code/data` 和 `/qr_code/direction`；不发布 `/qr_code/result_image`。

## 2. 二维码内容要求

当前比赛规则改为数字二维码：

```text
1~9999
```

方向判定：

```text
奇数 -> ClockWise      -> /sign_foxglove 发布 3
偶数 -> AntiClockWise  -> /sign_foxglove 发布 4
```

例如：

```text
5868 是偶数 -> AntiClockWise -> 发布 4
```

非数字、0、10000 及以上，都会被当成“未定义”。

如果画面里同时出现多个二维码，当前代码会优先选择面积最大的二维码。比赛测试时仍建议让摄像头主要看到一个二维码，避免并排二维码大小接近时选择不稳定。

## 3. 启动前确认

需要确认：

1. USB 摄像头能正常启动。
2. `/image` 话题存在。
3. `dg_pkg` 已经编译并 source。
4. 板端已安装二维码依赖：`pyzbar` 和系统 `zbar` 库。

如果缺依赖，常见现象是节点启动时报 `No module named pyzbar` 或找不到 `zbar`。

### 查看节点是否存在

> 📋 **贴到 MobaXterm 执行**：

```bash

```


### 查看节点订阅和发布

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc
ros2 node info /qrcode_detector
```

期望看到：

```text
Subscribers:
  /image: sensor_msgs/msg/CompressedImage

Publishers:
  /sign_foxglove: std_msgs/msg/Int32
  /qr_code/data: std_msgs/msg/String
  /qr_code/direction: std_msgs/msg/String
```

### 降低去抖帧数，便于快速测试

默认需要连续 5 帧识别一致才发布。调试时可以临时改成 2：

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc
ros2 run dg_pkg qrcode_detector --ros-args -p debounce_frames:=2
```

### 如果相机话题不是 `/image`

假设实际话题是 `/image/compressed`，可以这样指定：

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc
ros2 run dg_pkg qrcode_detector --ros-args -p camera_topic:=/image/compressed
```

但注意：该话题类型必须仍是 `sensor_msgs/msg/CompressedImage`。

## 7. 最小验收流程

1. 启动 USB 摄像头。
2. `ros2 topic hz /image` 有稳定频率。
3. 启动 `qrcode_detector`。
4. 另一个终端 `ros2 topic echo /sign_foxglove`。
5. 再开一个终端 `ros2 topic echo /qr_code/data`。
6. 将内容为奇数的二维码对准摄像头，观察是否输出原始数据和 `data: 3`。
7. 将内容为偶数的二维码对准摄像头，观察是否输出原始数据和 `data: 4`。

验收通过标准：

```text
1~9999 奇数    -> /qr_code/data 发布原始数字，/sign_foxglove 发布 3
1~9999 偶数    -> /qr_code/data 发布原始数字，/sign_foxglove 发布 4
无二维码       -> 不持续发布新信号
非数字/超范围   -> /qr_code/data 发布原始内容，/sign_foxglove 发布 0
```

## 8. 常见问题

### 8.1 `/image` 没有数据

检查摄像头 launch 是否启动：

```bash
ros2 topic list | grep image
ros2 topic info /image
```

如果没有 `/image`，先解决摄像头启动问题，不要改二维码节点。

### 8.2 节点启动但没有识别结果

优先检查：

1. 二维码内容是否为 `1~9999` 的整数。
2. 二维码是否清晰、光照是否足够。
3. 摄像头是否对焦，二维码是否在画面中央。
4. `debounce_frames` 是否太高，调试时可临时设为 2。

### 8.3 报 `pyzbar` 或 `zbar` 错误

需要安装依赖。可先检查：

```bash
python3 -c "from pyzbar.pyzbar import decode; print('pyzbar OK')"
```

如果失败，再安装依赖。具体安装命令要根据板端软件源情况处理，优先记录第一条错误再决定。

### 8.4 当前发布哪些二维码结果话题

```text
/qr_code/data       std_msgs/String，二维码原始内容
/qr_code/direction  std_msgs/String，ClockWise / AntiClockWise / unknown
/sign_foxglove      std_msgs/Int32，3 / 4 / 0
```

## 9. 后续接入状态机的建议

当前状态机只需要订阅：

```text
/sign_foxglove
```

信号解释：

```text
3 = ClockWise，奇数二维码
4 = AntiClockWise，偶数二维码
```

建议状态机只在 `TASK1_SCAN_QR` 状态下接受该信号，收到 3 或 4 后锁存结果，避免二维码一直在画面里导致重复触发。
