# 自动巡航最小闭环操作指南

> 目标：先完成任务 1+3：`P 点启动 -> 自动 initialpose -> QR 扫码 -> 指定通道进退 -> 返回 P 点 -> 停车`。
> 当前不包含黄色通道巡线、VLM、人形立牌识别和完整状态机。

## 1. 当前实现内容

核心节点：

```text
ros2 run dg_pkg nav_cruise
```

启动文件：

```text
ros2 launch dg_pkg dg_competition.launch.py
```

执行流程：

```text
INIT
  ↓
自动发布 /initialpose
  ↓
等待 Nav2 action server 就绪
  ↓
发车倒计时 start_delay_sec，默认 4 秒
  ↓
调用 Nav2 /navigate_to_pose 到 route_minimal[0]，当前为 qr_stop
  ↓
qrcode_detector 启动满 15 秒后才开始识别
  ↓
前往 qr_stop 途中若收到 /sign_foxglove=3/4，安全取消该目标并直接继续下一点
  ↓
若途中未识别，则到达 qr_stop 后继续等待 /sign_foxglove=3/4
  ↓
按 route_minimal 剩余航点继续导航，当前为 return_mid_after_qr -> task13_channel_near -> p_return
  ↓
到达 task13_channel_near 后等待速度链静置 1.2 秒
  ↓
开环直行 0.55m（+0.20m/s）-> 保持零速 1.0 秒 -> 开环后退 0.55m（-0.20m/s）-> 停车
  ↓
发布 /cmd_vel = 0 停车
  ↓
FINISH
```

状态话题：

```text
/competition/state  std_msgs/String
```

二维码信号：

```text
/sign_foxglove = 3  ClockWise
/sign_foxglove = 4  AntiClockWise
```

## 3. 启动前置条件

必须已经启动并验收：

```text
1. 底盘 origincar_base
2. EKF /odom_combined
3. 雷达 /scan
4. Nav2 dg_nav2.launch.py，所有 lifecycle active
5. RViz 中 /scan 与地图墙面基本贴合
6. USB 摄像头 /image 正常
```

如果只想先测试自动导航流程、不真实扫码，可以不启动摄像头和 qrcode_detector，后面手动发布 `/sign_foxglove`。

注意：`nav_cruise` 只是“给 Nav2 发任务”的节点，不负责启动底盘、EKF、雷达和 Nav2。  
如果直接启动 `dg_competition.launch.py`，但 Nav2 没有全 active，常见现象是：

```text
nav_cruise process has died
/competition/state 没有发布
/cmd_vel 没有发布
ros2 action list 里没有 /navigate_to_pose
或 Nav2 只有 map_server/amcl active，planner/controller/bt_navigator inactive
```

## 4. 完整启动顺序

首次验收建议按下面顺序开终端。建议先做一次“环境变量写入 `~/.bashrc`”，以后每个终端只需要执行：

```bash
source ~/.bashrc
```

### 4.0 一次性写入 ROS 环境到 `~/.bashrc`

只需要在小车上执行一次。执行后，重新 SSH 登录通常会自动加载；已经打开的旧终端仍需手动 `source ~/.bashrc`。

> 📋 **贴到 MobaXterm 执行**：

```bash
grep -q "DG_ROS_ENV_START" ~/.bashrc || cat >> ~/.bashrc <<'EOF'

# DG_ROS_ENV_START
source /opt/tros/humble/setup.bash
if [ -f /userdata/dev_ws/install/setup.bash ]; then
  source /userdata/dev_ws/install/setup.bash
fi
export ROS_DOMAIN_ID=30
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
# DG_ROS_ENV_END
EOF

source ~/.bashrc

echo "ROS_DOMAIN_ID=$ROS_DOMAIN_ID"
echo "RMW_IMPLEMENTATION=$RMW_IMPLEMENTATION"
ros2 pkg list | grep dg_pkg
```

期望：

```text
ROS_DOMAIN_ID=30
RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
能看到 dg_pkg
```

后续本文所有终端命令默认只写 `source ~/.bashrc`。如果 `colcon build` 刚刚完成，也建议在当前终端再执行一次 `source ~/.bashrc`，让新安装入口立即生效。

### 终端 1：启动底盘

> 📋 **贴到 MobaXterm 执行**（先 SSH 进小车；连接前请确认实际 IP、账号和密码）：

```bash
source ~/.bashrc

ros2 launch origincar_base origincar_bringup.launch.py carto_slam:=true
```

`carto_slam:=true` 是关键参数：它会禁止底盘 launch 内的默认 EKF。  
本项目导航使用终端 2 的自定义 EKF 发布 `odom -> base_footprint` 和 `/odom_combined`。如果漏掉这个参数，可能出现两个 EKF 或两套 odom/TF 树，Nav2 会报：

```text
Could not find a connection between 'odom' and 'base_footprint'
Tf has two or more unconnected trees.
```

### 终端 2：启动 EKF

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc

ros2 run robot_localization ekf_node --ros-args \
  --params-file /userdata/dev_ws/src/ekf_no_imu_yaw.yaml \
  -r odometry/filtered:=odom_combined
```

### 终端 3：启动雷达

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc

ros2 launch lslidar_driver lsn10_launch.py
```

### 终端 4：启动 Nav2

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc

ros2 launch dg_pkg dg_nav2.launch.py map:=/root/maps/competition_map.yaml
```

### 终端 5：检查 Nav2 是否真的可用

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc

echo "=== nav action ==="
ros2 action list | grep navigate

echo "=== lifecycle ==="
for n in map_server amcl planner_server controller_server smoother_server behavior_server bt_navigator waypoint_follower velocity_smoother; do
  echo "=== $n ==="
  ros2 lifecycle get /$n 2>/dev/null || true
done

echo "=== rates ==="
timeout 4 ros2 topic hz /scan
timeout 4 ros2 topic hz /odom_combined
```

期望：

```text
/navigate_to_pose
/navigate_through_poses

map_server: active [3]
amcl: active [3]
planner_server: active [3]
controller_server: active [3]
smoother_server: active [3]
behavior_server: active [3]
bt_navigator: active [3]
waypoint_follower: active [3]
velocity_smoother: active [3]

/scan 有稳定频率
/odom_combined 有稳定频率
```

如果只有 `map_server`、`amcl` active，后面的节点 inactive，先不要启动自动巡航。通常是底盘、EKF、雷达、TF 或 `/scan` 前置链路没启动完整。

### 终端 6：启动 USB 摄像头

如果本轮要真实识别二维码，必须先启动 USB 摄像头并确认 `/image` 有数据。

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc

ros2 launch origincar_bringup usb_websocket_display.launch.py
```

另开一个终端检查：

```bash
source ~/.bashrc
ros2 topic info /image
timeout 5 ros2 topic hz /image
```

期望：

```text
Type: sensor_msgs/msg/CompressedImage
Publisher count >= 1
average rate: 有稳定频率
```

如果只做手动二维码信号验收，即 `start_qrcode:=false`，可以暂时不启动摄像头。

### 终端 7：启动自动巡航

首次建议先关闭真实二维码识别，用手动信号验收：

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc

ros2 launch dg_pkg dg_competition.launch.py start_qrcode:=false start_display:=false
```

等状态进入 `WAIT_QR_SIGNAL` 后，再在另一个终端手动发布二维码方向，见第 6 节。

## 6. 推荐首次验收：手动二维码信号

首次建议不要让二维码识别影响判断。先只测：

```text
自动 initialpose -> 到 QR -> 手动发 3/4 -> 回 P
```

### 终端 A：启动自动巡航，不启动 qrcode_detector

如果已经按第 4 节启动过自动巡航，这一步不用重复执行。

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc

ros2 launch dg_pkg dg_competition.launch.py start_qrcode:=false start_display:=false
```

### 终端 B：观察状态

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc
ros2 topic echo /competition/state
```

### 终端 C：到达 QR 点后手动发布二维码方向

当终端 A 输出正在等待二维码，或 `/competition/state` 显示：

```text
WAIT_QR_SIGNAL
```

发布一个方向：

```bash
source ~/.bashrc
ros2 topic pub --once /sign_foxglove std_msgs/msg/Int32 "{data: 3}"
```

或者：

```bash
ros2 topic pub --once /sign_foxglove std_msgs/msg/Int32 "{data: 4}"
```

之后小车应自动导航回 P 点并停车。

## 7. 联合二维码识别验收

如果手动信号验收通过，再启用二维码识别：

启用前必须确认终端 6 的 USB 摄像头已经启动，且 `/image` 是
`sensor_msgs/msg/CompressedImage` 并有稳定频率。否则 `qrcode_detector`
会启动，但不会识别到任何二维码，`nav_cruise` 会一直停在 `WAIT_QR_SIGNAL`。

```bash
source ~/.bashrc

ros2 launch dg_pkg dg_competition.launch.py \
  start_qrcode:=true \
  start_display:=false \
  debounce_frames:=2 \
  qr_scan_start_delay_sec:=15.0
```

默认发车延迟由 `competition_params.yaml` 控制：

```yaml
navigation:
  start_delay_sec: 4.0
```

如果只是临时测试，可以直接覆盖：

```bash
source ~/.bashrc

ros2 launch dg_pkg dg_competition.launch.py \
  start_qrcode:=true \
  start_display:=false \
  debounce_frames:=2 \
  qr_scan_start_delay_sec:=15.0 \
  start_delay_sec:=4.0
```

说明：

```text
start_delay_sec=-1.0  使用 competition_params.yaml 中的 start_delay_sec
start_delay_sec=4.0   Nav2 就绪并发布 initialpose 后，等待 4 秒再发送第一个导航目标
start_delay_sec=0.0   不等待，立即发送第一个导航目标
qr_scan_start_delay_sec=15.0  qrcode_detector 启动后的前 15 秒忽略图像，第 15 秒后开始识别
```

二维码识别节点启动满 15 秒后，把二维码放到摄像头前。只要途中识别出合法
二维码，就会取消尚未完成的 `qr_stop` 目标并直接前往下一点；如果一直没有识别，
小车仍会到达 QR 点并等待，不会自动跳过。

```text
奇数 -> /sign_foxglove = 3 -> 返回 P
偶数 -> /sign_foxglove = 4 -> 返回 P
```

如果要同时显示到 7 寸屏，请先确保 X11 授权已做：

```bash
xhost +SI:localuser:root
```

然后启动时加：

```bash
start_display:=true
```

如果从 SSH 启动屏幕显示，可能还需要：

```bash
export DISPLAY=:0
```

## 8. 关键参数

参数文件：

```text
/userdata/dev_ws/src/dg_pkg/config/competition_params.yaml
```

Nav2 速度和到点容差在：

```text
/userdata/dev_ws/src/dg_pkg/config/nav2_params.yaml
```

当前调试值：

```yaml
behavior_tree:
  global_replanning_frequency: 0.333  # Hz，约每 3 秒

controller_server:
  FollowPath:
    desired_linear_vel: 0.18
    min_lookahead_dist: 0.35
    max_lookahead_dist: 0.70
    lookahead_time: 0.4
    regulated_linear_scaling_min_radius: 0.4
    regulated_linear_scaling_min_speed: 0.08
    max_angular_accel: 1.5
  general_goal_checker:
    xy_goal_tolerance: 0.10
    yaw_goal_tolerance: 0.45

velocity_smoother:
  max_velocity: [0.18, 0.0, 0.35]
  min_velocity: [-0.12, 0.0, -0.35]

planner_server:
  GridBased:
    reverse_penalty: 8.0
    change_penalty: 2.0
    non_straight_penalty: 1.4
    cost_penalty: 3.0

global_costmap:
  obstacle_layer:
    obstacle_max_range: 4.5
    raytrace_max_range: 5.0
  inflation_layer:
    inflation_radius: 0.30

local_costmap:
  obstacle_layer:
    obstacle_max_range: 2.5
    raytrace_max_range: 3.0
  inflation_layer:
    inflation_radius: 0.25
```

说明：

```text
1. 直线巡航速度当前是 0.18m/s，不是 1.8m/s 或 1.5m/s。
2. 当前 RPP 稳定跟踪档使用 `min_lookahead_dist=0.35`、`max_lookahead_dist=0.70`、`lookahead_time=0.4`，减少近距离路径抖动。
3. `regulated_linear_scaling_min_radius=0.4`、`regulated_linear_scaling_min_speed=0.08`，急弯会更稳但可能略慢。
4. 角速度上限在 velocity_smoother 中限制为 `0.35rad/s`；不要在 FollowPath 中添加 Humble RPP 可能不读取的 `max_angular_vel`。
5. 倒车线速度当前已提高到 -0.12m/s；如果 QR 后倒车外甩、剐蹭或回 P 不稳，优先回退到 -0.08 或 -0.06。
6. `non_straight_penalty=1.4` 用于让 Smac 更偏向少转弯；`reverse_penalty=8.0` 和 `change_penalty=2.0` 本轮保持不变。
7. `cost_scaling_factor=2.5` 是代价衰减系数，不是扩张距离；当前全局规划层为 `global_costmap.inflation_radius=0.30`，局部层提高到 `local_costmap.inflation_radius=0.25`，加强近场避障和碰撞预测安全余量。
8. 两棵阿克曼安全 BT 当前使用 `RateController hz=0.333`，约每 3 秒重新调用一次 Smac 全局规划；RPP 控制循环仍为 20Hz。该调整用于更早把后续扫描到的随机静态路障纳入新路径，同时避免恢复到 1Hz 时路线频繁跳变。
9. 全局障碍标记范围提高到 `4.5m`，配套射线范围为 `5.0m`；局部仍保持 `2.5m/3.0m`。这只能提前纳入雷达视线内且实际被 `/scan` 观测到的障碍，不能看到被墙或其他路障遮挡的障碍。
```

```yaml
    - "p_return"
```

`nav_cruise.py` 会按 `route_minimal` 顺序执行；第一点默认为 QR 点，到达第一点后等待 `/sign_foxglove=3/4`，之后继续执行剩余返航点。以后加点不再需要改代码。

`start_delay_sec` 是发车倒计时。当前默认 `4.0` 秒；倒计时发生在：

```text
发布 initialpose 完成
  ↓
Nav2 action server 已就绪
  ↓
等待 start_delay_sec
  ↓
发送第一个 Nav2 goal，开始发车
```

当前建议：

```yaml
auto_compute_goal_yaw: false
```

含义：`nav_cruise.py` 使用 `competition_params.yaml` 中每个 waypoint 保存的踩点角度。这样到达 QR 点时会尽量使用采集 QR 点时保存的朝向，而不是按“上一点 -> 目标点”的连线方向自动计算 yaw。

如果某个航点只要求到点、不要求最终朝向，可以在该 waypoint 下加：

```yaml
ignore_yaw: true
```

当前 `p_return` 已设置 `ignore_yaw: true`。`nav_cruise.py` 导航到该点前会临时设置：

```text
/controller_server general_goal_checker.yaw_goal_tolerance = 3.14
```

这样返回 P 点时只要求位置进入容差，不会为了最终角度在 P 点附近硬转，降低撞上 P 点附近路障的风险。普通航点会恢复为：

```text
/controller_server general_goal_checker.yaw_goal_tolerance = 0.45
```

当前 `p_return` 还设置了到点后低速直走补偿：

```yaml
post_arrival_forward_distance_m: 0.15
post_arrival_forward_speed_mps: 0.05
```

含义：Nav2 判断到达 `p_return` 后，`nav_cruise.py` 会按当前车头方向开环直走约 15cm，让车体更完整进入 P 点区域。因为这是开环动作，必须保证到达 `p_return` 时车头大致朝向 P 区内部；如果发现前进方向不对，优先调整 `p_return` 或返航中间点姿态，不要盲目增加距离。

当前通道进退同样是开环动作：

```yaml
post_arrival_settle_sec: 1.2
post_arrival_forward_distance_m: 0.55
post_arrival_forward_speed_mps: 0.20
post_arrival_reverse_distance_m: 0.55
post_arrival_reverse_speed_mps: 0.20
post_arrival_direction_change_pause_sec: 1.0
```

`post_arrival_settle_sec` 用于等待 Nav2 的 velocity smoother 停止输出，避免两个
`/cmd_vel` 发布者互相抢命令。该段不经过全局路径规划和局部碰撞预测，首次只能在
通道内无障碍、后方净空、有人可立即急停的情况下低风险验证。

前进结束后先连续发布零速并保持 1 秒，再发送负速度，避免底盘尚未完全停止时
直接从正转切换到反转。正常日志顺序应为：

```text
状态切换: POST_MOTION_FORWARD
前进结束，保持零速 1.00s 后再后退
状态切换: POST_MOTION_DIRECTION_CHANGE_PAUSE
状态切换: POST_MOTION_REVERSE
```

如果后续希望小车始终沿路径切线朝向进入目标点，再改回：

```yaml
auto_compute_goal_yaw: true
```

## 9. 安全注意

- 首次不要长距离高速测试；Nav2 速度仍由 `nav2_params.yaml` 控制。
- 如果小车贴墙、绕圈、快速倒车或路径明显异常，立即发零速度。
- 通道 `+0.55m/-0.55m` 是开环直线动作，不会主动绕开临时障碍；正式使用前必须确认通道内与车后方净空。
- 不要同时运行两个 `nav_cruise`。
- 不要同时运行两套 Nav2。
- 如果自动 initialpose 后 `/scan` 没贴墙，先停，不要继续发 goal。

紧急停车：

```bash
source ~/.bashrc
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
"{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
```
