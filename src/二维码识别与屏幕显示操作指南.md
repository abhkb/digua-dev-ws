# 二维码识别与屏幕显示操作指南

> 目标：启动 USB 摄像头，运行二维码识别节点 `qrcode_detector`，再运行 7 寸屏显示节点 `qr_result_display`，让顺/逆时针结果自动显示在小车屏幕上。  
> 当前规则：二维码内容为 `1~9999`，奇数代表顺时针，偶数代表逆时针。

## 1. 整体流程

```text
启动 USB 摄像头
  ↓ 发布 /image
启动 qrcode_detector
  ↓ 识别数字二维码
  ↓ 发布原始数据 /qr_code/data
  ↓ 奇数发布 /sign_foxglove = 3
  ↓ 偶数发布 /sign_foxglove = 4
启动 qr_result_display
  ↓ 收到原始数据，屏幕显示“二维码原始数据：xxxx”
  ↓ 收到 3，读取 clockwise.txt，全屏显示顺时针
  ↓ 收到 4，读取 anticlockwise.txt，全屏显示逆时针
```

推荐启动顺序：

```text
1. 启动 USB 摄像头
2. 启动 qrcode_detector
3. 启动 qr_result_display
4. 扫描二维码并观察屏幕
```

说明：`qr_result_display` 也可以先启动，它会先显示等待二维码。为了和比赛流程一致，本文按“摄像头 → 识别 → 显示”的顺序写。

## 2. 当前话题和信号

| 模块 | 输入 | 输出 |
|---|---|---|
| USB 摄像头 | 摄像头画面 | `/image`，`sensor_msgs/msg/CompressedImage` |
| `qrcode_detector` | `/image` | `/sign_foxglove`，`std_msgs/msg/Int32` |
| `qrcode_detector` | `/image` | `/qr_code/data`，`std_msgs/msg/String`，二维码原始内容 |
| `qrcode_detector` | `/image` | `/qr_code/direction`，`std_msgs/msg/String`，方向字符串 |
| `qr_result_display` | `/sign_foxglove` + `/qr_code/data` | 7 寸屏全屏文字 + 原始数据 |

二维码规则：

```text
1~9999 奇数 -> /qr_code/data 原始数字 -> ClockWise     -> /sign_foxglove = 3 -> 屏幕显示顺时针和原始数据
1~9999 偶数 -> /qr_code/data 原始数字 -> AntiClockWise -> /sign_foxglove = 4 -> 屏幕显示逆时针和原始数据
```

例如：

```text
1357 -> 奇数 -> /qr_code/data: "1357" -> /sign_foxglove: 3 -> 顺时针
5868 -> 偶数 -> /qr_code/data: "5868" -> /sign_foxglove: 4 -> 逆时针
```

非数字、`0`、`10000` 及以上会被判定为未定义，会发布原始数据、`/qr_code/direction=unknown`、`/sign_foxglove=0`。

## 4. 启动前检查

### 4.1 编译 `dg_pkg`

> 📋 **贴到 MobaXterm 执行**（先 SSH 进小车；连接前请确认实际 IP、账号和密码）：

```bash
cd /userdata/dev_ws
source /opt/tros/humble/setup.bash
colcon build --packages-select dg_pkg --symlink-install
source install/setup.bash
```

### 4.2 检查可执行入口

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc
ros2 pkg executables dg_pkg | grep -E "qrcode_detector|qr_result_display"
```

期望看到：

```text
dg_pkg qrcode_detector
dg_pkg qr_result_display
```

### 4.3 检查 tkinter

屏幕显示节点使用 `tkinter`。先检查：

> 📋 **贴到 MobaXterm 执行**：

```bash
python3 -c "import tkinter; print('tkinter OK')"
```

如果失败，再尝试安装：

```bash
sudo apt install -y python3-tk
```

### 4.4 如果从 MobaXterm 启动屏幕窗口

如果你不是在 7 寸屏本机终端启动，而是在 MobaXterm 的 SSH 终端启动 `qr_result_display`，需要先在 7 寸屏本机桌面终端执行一次：

```bash
xhost +SI:localuser:root
```

这条命令一般每次图形桌面会话执行一次即可：

```text
同一次桌面登录期间：一般只执行一次即可
重启小车后：需要重新执行
注销/重进桌面后：需要重新执行
X server 重启后：需要重新执行
```

## 5. 正式启动流程

### 终端 1：启动 USB 摄像头

> 📋 **贴到 MobaXterm 执行**：

```bash
source /opt/tros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp

ros2 launch origincar_bringup usb_websocket_display.launch.py
```

启动后可在浏览器打开：

```text
http://<小车IP>:8000
```

选择 web 展示端，确认摄像头画面正常。

### 终端 2：确认 `/image`

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc
ros2 topic info /image
timeout 5 ros2 topic hz /image
```

期望：

```text
Type: sensor_msgs/msg/CompressedImage
Publisher count: 1 或更多
average rate: 有稳定频率
```

### 终端 3：启动二维码识别

调试时建议把去抖帧数降到 2，识别更快：

> 📋 **贴到 MobaXterm 执行**：

```bash
source /opt/tros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp

ros2 run dg_pkg qrcode_detector --ros-args -p debounce_frames:=2
```

正式比赛可以用默认值：

```bash
ros2 run dg_pkg qrcode_detector
```

### 终端 4：启动屏幕显示

如果在 MobaXterm 启动，记得设置 `DISPLAY=:0`：

> 📋 **贴到 MobaXterm 执行**：

```bash
source /opt/tros/humble/setup.bash
source /userdata/dev_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export DISPLAY=:0

ros2 run dg_pkg qr_result_display
```

如果是在 7 寸屏本机终端启动，也可以执行同样命令；通常不需要 `xhost` 授权。

### 终端 5：观察信号和原始数据，可选

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc
ros2 topic echo /sign_foxglove
```

另一个终端可以观察原始二维码内容：

```bash
source ~/.bashrc
ros2 topic echo /qr_code/data
```

扫二维码时应看到：

```text
data: 3
```

或：

```text
data: 4
```

同时 `/qr_code/data` 应看到类似：

```text
data: '5868'
```

## 6. 最小验收

### 6.1 手动发布测试屏幕

不启动摄像头也可以先测屏幕：

> 📋 **贴到 MobaXterm 执行**：

```bash
source ~/.bashrc
ros2 topic pub --once /qr_code/data std_msgs/msg/String "{data: '1357'}"
ros2 topic pub --once /sign_foxglove std_msgs/msg/Int32 "{data: 3}"
```

期望：屏幕显示顺时针，并显示 `二维码原始数据：1357`。

再执行：

```bash
ros2 topic pub --once /qr_code/data std_msgs/msg/String "{data: '5868'}"
ros2 topic pub --once /sign_foxglove std_msgs/msg/Int32 "{data: 4}"
```

期望：屏幕显示逆时针，并显示 `二维码原始数据：5868`。

### 6.2 摄像头 + 二维码 + 屏幕完整测试

1. 启动 USB 摄像头。
2. 启动 `qrcode_detector`。
3. 启动 `qr_result_display`。
4. 扫奇数二维码，终端应输出 `/qr_code/data` 原始数字和 `/sign_foxglove data: 3`，屏幕显示顺时针与原始数据。
5. 扫偶数二维码，终端应输出 `/qr_code/data` 原始数字和 `/sign_foxglove data: 4`，屏幕显示逆时针与原始数据。

验收标准：

```text
奇数二维码 -> /qr_code/data = 原始数字 -> /sign_foxglove = 3 -> 屏幕显示顺时针和原始数据
偶数二维码 -> /qr_code/data = 原始数字 -> /sign_foxglove = 4 -> 屏幕显示逆时针和原始数据
无二维码   -> 不持续发布新信号
非法内容   -> /qr_code/data = 原始内容，/sign_foxglove = 0，屏幕显示未知二维码和原始数据
```

## 9. 常见问题

### 9.1 MobaXterm 启动屏幕时报 display 权限错误

如果出现：

```text
Authorization required, but no authorization protocol specified
_tkinter.TclError: couldn't connect to display ":0"
```

在 7 寸屏本机桌面终端执行：

```bash
xhost +SI:localuser:root
```

然后回到 MobaXterm 重新执行：

```bash
source ~/.bashrc
export DISPLAY=:0
ros2 run dg_pkg qr_result_display
```

### 9.2 `/image` 没有数据

检查摄像头：

```bash
ros2 topic list | grep image
ros2 topic info /image
```

如果没有 `/image`，先解决摄像头启动问题。

### 9.3 二维码识别到但显示未定义

确认二维码内容：

```text
必须是 1~9999 的整数
```

例如：

```text
5868 -> 合法，偶数，逆时针
0    -> 非法
abc  -> 非法
10000 -> 非法
```

### 9.4 中文显示成方块

安装中文字体：

```bash
sudo apt install -y fonts-wqy-zenhei fonts-wqy-microhei
```

然后重启 `qr_result_display`。
